# 配置持久化与恢复

持久化的运行设置位于 `data/config.json`。Go 配置服务在 `internal/config` 中负责读取、校验、写入和变更通知。环境凭据的加载路径为 `data/.env`。提示词有各自的文件和保存入口。

## 选择写入接口

| 接口 | 使用场景 |
| --- | --- |
| `Config.UpdateConfig(mutator)` | 在文件锁保护下读取最新配置，并修改业务负责的字段 |
| `Config.SaveConfigMap(doc)` | 调用方明确持有完整的候选配置时保存全部映射 |
| `Config.RawSnapshot()` | 读取防御性快照，提供查询界面或检查 |
| `Config.SavePrompt(kind, content)` | 保存总结、投票或助手提示词 |
| `Config.Subscribe(priority, handler)` | 订阅合法配置变更，用于刷新业务组件 |

业务处理器通过配置接口更新自己的分区。模型厂商 API 在保存时检查 `revision`，频道配置信息由相应领域的更新方法持久化。 `/setaicfg` 的「保留当前值」在提交时保留该字段的最新值。首次语言选择使用个人语言设置。

## 写入和恢复

事务在同一把互斥锁和操作系统文件锁下完成读取、校验、备份与替换，锁文件为 `config.json.lock`。同目录临时文件写入成功才原子替换目标。读取、校验、备份或替换失败会向调用方返回错误。

- `config.json.last_valid` 保存有效恢复点。
- `config.json.backups/` 保存最多 30 个独立有效快照，使用 UTC 时间命名。重复内容会去重。
- 热重载校验失败时，配置服务在文件锁保护下从有效备份、`last_valid` 或内存快照恢复。
- 业务入口在成功提交后才使用新配置，发布变更事件并刷新相关组件。

配置备份可能包含真实凭据。应限制文件及数据目录的访问权限，故障反馈只保留脱敏内容。

## 人工恢复

先停止写配置的进程并保存事故现场。核对候选快照可以解析，并包含完整频道、调度、转发和 AI 配置，再按[部署回滚流程](Release-2.6.0.md#升级顺序)恢复。历史快照与运行数据备份需要分别管理。
