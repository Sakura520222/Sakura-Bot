# Sakura 智能问答Bot 使用指南

## 📖 简介

Sakura 智能问答Bot 是一个独立的 Telegram Bot（与主 Bot 使用不同的 Token），由主 Bot 进程作为子进程托管运行，专门用于查询频道历史总结与已入库的频道消息。它支持自然语言交互，让你像对话一样轻松获取频道信息。

### ✨ 核心特点

- 🎯 **自然语言查询** - 无需命令前缀，直接提问
- 🧠 **智能意图识别** - 自动理解你的查询意图
- 📊 **上下文感知** - 基于频道画像生成更精准的回答
- 🔍 **多维度检索** - 支持语义向量、时间、关键词、主题等多条件检索
- 🎫 **使用配额管理** - 防止滥用，保障服务稳定性
- 🧩 **双运行时** - v2.2.0 起缺省运行轻量 Go 二进制，可在线切换回 Python
- 🛡️ **封禁申诉入口** - 兼作助手 Bot，受理 Sakura Guard 封禁申诉

## 🚀 快速开始

### 1. 创建问答Bot

访问 [@BotFather](https://t.me/BotFather)，创建一个新的Bot：
- 使用 `/newbot` 命令
- 按提示设置Bot名称和用户名
- **重要**：必须与主Bot（总结Bot）使用不同的Bot Token

### 2. 配置环境变量

在 `data/.env` 文件中添加以下配置：

```env
# ===== 问答Bot配置 =====
# 问答Bot的Token（从@BotFather获取，必须与主Bot不同）
QA_BOT_TOKEN=your_qa_bot_token_here

# 是否启用问答Bot（True/False）
QA_BOT_ENABLED=True

# 问答Bot使用限制配置
# 每个用户每日限额（默认3次）
QA_BOT_USER_LIMIT=3

# 每日总限额（默认200次）
QA_BOT_DAILY_LIMIT=200
```

### 3. 启动问答Bot

问答 Bot 由主 Bot 进程自动托管启动，无需单独部署。配置好 `QA_BOT_ENABLED=True` 与 `QA_BOT_TOKEN` 后，正常启动主 Bot 即可：

```bash
# 本地源码运行
python main.py

# Docker Compose（问答 Bot 随主容器自动启动）
docker compose up -d
```

> 问答 Bot 作为主容器内的子进程运行（缺省使用轻量 Go 二进制 `sakura-qa`）。`docker-compose.yml` 只有 `sakura-summary-bot` 一个服务，不要在其中另建独立的 `qa_bot` 服务。

如需临时单独运行 Python 版问答 Bot（如本地调试），可执行 `python qa_bot.py`；注意不要与主 Bot 托管的问答 Bot 同时使用同一个 Token。

### 4. 开始使用

在Telegram中找到你创建的问答Bot，发送 `/start` 命令开始使用！

## 🎯 查询类型

问答Bot支持以下查询类型：

### 1. 总结查询

**示例**：
- "上周发生了什么？"
- "今天有什么更新？"
- "本周有什么重要事件？"

**特点**：
- 基于时间范围查询历史总结
- AI智能提取关键事件并生成连贯回答
- 支持多频道综合查询

### 2. 关键词查询

**示例**：
- "提到GPT-4的内容"
- "技术讨论相关"
- "Python相关话题"

**特点**：
- 在总结文本和元数据中搜索关键词
- 返回相关度最高的总结
- 支持多个关键词组合查询

### 3. 主题查询

**示例**：
- "有什么技术讨论？"
- "最近有什么新闻？"
- "关于更新的内容"

**特点**：
- 基于预定义主题标签检索
- AI自动识别总结主题
- 支持主题过滤和时间范围

### 4. 统计查询

**示例**：
- "系统统计"
- "有多少条总结？"
- "频道排名"

**特点**：
- 返回统计数据和排名
- 支持多频道对比
- 实时更新

### 5. 状态查询

**示例**：
- "配额状态"
- "还能问几次？"
- "今日使用量"

**特点**：
- 查看个人配额使用情况
- 显示系统总配额状态
- 实时更新

## ⚙️ 使用限制

### 配额管理

#### 普通用户

- **每日限额**：3次
- **说明**：
  - 每日00:00（UTC）自动重置
  - 配额用尽后需等待次日重置
  - 返回配额状态提示

#### 殡理员

- **每日限额**：无限制
- **说明**：
  - 管理员ID在 `data/.env` 中配置
  - 不受配额限制
  - 可随时使用

#### 系统总限额

- **每日总限额**：200次
- **说明**：
  - 所有用户的总使用次数
  - 达到总限额后，非管理员用户无法使用
  - 每日00:00自动重置

### 配额查询命令

```
/status - 查看你的配额使用状态
```

### 调整配额

配额限额支持运行时调整（热生效，无需重启）：

- `config.json` 的 `qa_bot_quota`（`user_daily_limit` / `total_daily_limit`）优先生效；
- 环境变量 `QA_BOT_USER_LIMIT` / `QA_BOT_DAILY_LIMIT` 作为部署级兜底；
- 也可在 WebUI「AI 配置」页的问答配额面板在线调整。

## 🛡️ 封禁申诉

问答 Bot 同时作为助手 Bot 提供封禁申诉入口。被 Sakura Guard 封禁的用户私聊问答 Bot，点击「🚫 封禁申诉」或发送 `/appeal`，即可对 Guard 已记录的封禁（含验证失败封禁与永久黑名单案件）提交申诉。申诉材料、审核决定和通知都通过 MySQL 与主 Bot 交换，不占用问答配额。

| 命令 | 说明 |
|------|------|
| `/appeal` | 自助提交封禁申诉 |
| `/appeals` | 查看本人申诉与处理进度 |
| `/cancel_appeal` | 取消当前申诉或审核输入 |

说明填写最多 2000 字，可追加文字、照片、视频或文档（每轮最多 5 个附件、单个最大 20 MB）；草稿存入 MySQL，重启不丢失，24 小时未提交自动撤回。等待审核期间可补充材料或撤回；管理员要求补充时，在卡片点击「补充材料」提交即可。

申诉的完整流程、管理员审核方式与状态说明见 [Sakura Guard 智能群管 › 自助封禁申诉](User-Sakura-Guard.md#自助封禁申诉)。

## 🔧 技术原理

### 系统架构

问答 Bot 与主 Bot 共享 MySQL 数据库，由主 Bot 进程作为子进程托管（缺省 Go 运行时）：

```
┌─────────────────────────────────────────────────────┐
│  主Bot（总结Bot，main.py）                            │
│  - 频道监控和总结                                      │
│  - 投票功能                                          │
│  - 管理员命令                                         │
│  - 子进程托管问答 Bot                                 │
└──────────┬──────────────────────────────────────────┘
           │
           │ 共享数据库（MySQL）
           │
           ↓
┌─────────────────────────────────────────────────────┐
│  问答Bot（智能助手）                                  │
│  - 自然语言对话接口（串行分发、流式回复）              │
│  - 问答引擎 QAEngineV3（agentic 工具调用）             │
│  - 会话管理器（多轮上下文）                            │
│  - 配额管理器                                         │
└─────────────────────────────────────────────────────┘
```

### 问答引擎（QAEngineV3）

回答生成采用「agentic 工具调用 + 降级」的两段式流程：

1. **Agentic 阶段**：LLM 自主决定是否检索以及调用哪些工具，包括：
   - `semantic_search`：向量语义检索（总结与原始消息两个集合，可选重排序）
   - 关键词检索：按关键词、主题、频道、时间范围查询历史总结
   - 频道上下文与统计查询等辅助工具
2. **无工具降级**：模型不支持工具调用或工具链路异常时，回退为结合多轮会话上下文的直连对话，保证仍能正常回答。

### 核心模块

#### 1. 问答引擎（QAEngineV3）

编排检索与生成：
- agentic 工具调用与流式输出
- 检索结果与多轮上下文组装
- 降级方案（无工具直连对话）

#### 2. 记忆管理器（MemoryManager）

管理和检索频道信息：
- 频道画像（Channel Profile）
- 关键词和主题索引
- 时间范围过滤
- 智能搜索

#### 3. 会话管理器（ConversationManager）

管理多轮对话：
- 会话创建与超时管理（30 分钟无交互开启新会话）
- 对话历史持久化（MySQL）
- 历史上下文注入与清理

#### 4. 配额管理器（QuotaManager）

管理使用配额：
- 用户配额检查
- 总配额控制
- 自动重置机制
- 管理员豁免

### 双运行时（Go / Python）

v2.2.0 起问答子进程缺省运行 Go 静态二进制（`qa-bot-go/`，稳态内存约 17-20MB，Python 版约 137MB，均为 v2.2.0 生产实测），行为与 Python 版逐条对齐；Go 二进制缺失时自动回退 Python。管理员可通过 `/qa_runtime` 命令或 WebUI「系统」页在线切换，详见 [运行时占用优化](Developer-Runtime-Footprint-Optimization.md) 与 [问答 Bot 实施](Developer-QA-Bot-Implementation.md)。

### 数据流

```
用户查询 → 配额检查 → 会话上下文加载 → agentic 检索（语义 + 关键词）→ AI 流式生成 → 返回回答
```

## 🛠️ 故障排除

### 常见问题

#### 1. Bot无响应

**可能原因**：
- Bot未启动
- Token配置错误
- 网络连接问题

**解决方法**：
```bash
# 查看主容器状态（问答 Bot 在其中作为子进程运行）
docker compose ps

# 查看主容器日志（含问答子进程输出）
docker compose logs -f sakura-summary-bot

# 查看问答 Bot 组件日志
docker compose exec sakura-summary-bot tail -n 100 logs/qa-bot.log

# 重启主容器（问答 Bot 随之重启）
docker compose restart
```

管理员也可在 Telegram 中发送 `/qa_status` 查看问答 Bot 运行状态，或 `/qa_restart` 重启问答 Bot。

#### 2. 配额不足

**提示信息**：
```
⚠️ 今日配额已用尽（3/3），请明天再试。
💡 每日00:00自动重置
```

**解决方法**：
- 等待次日自动重置
- 联系管理员申请豁免
- 考虑部署独立实例

#### 3. 未找到相关总结

**提示信息**：
```
🔍 未找到相关总结。

💡 提示：尝试调整关键词或时间范围。
```

**解决方法**：
- 扩大时间范围
- 调整关键词
- 确认频道有总结数据

#### 4. AI生成失败

**提示信息**：
```
❌ 处理查询时出错，请稍后重试。
```

**解决方法**：
- 稍后重试（工具链路异常时会自动降级为无工具直连对话）
- 检查AI API配置
- 查看日志排查问题

## 📊 性能优化

### 数据库优化

- **MySQL 连接池**：复用数据库连接（`MYSQL_POOL_SIZE` 可调，缺省 5）
- **跨进程协作**：问答 Bot 与主 Bot 通过 MySQL 表交换请求与通知，各自轮询处理
- **索引优化**：关键字段建立索引

### AI优化

- **提示词优化**：精简高效的提示词
- **温度控制**：平衡创造性和准确性
- **降级方案**：工具链路异常时自动降级为无工具直连对话

### 配额管理

- **自动重置**：每日00:00自动重置
- **并发控制**：问答消息串行分发处理，避免并发扣减竞态
- **灵活配置**：支持运行时调整限额（见上文「调整配额」）

---

## 🔒 安全与隐私

### 数据安全

- **访问控制**：用户仅能查询频道总结与已入库的频道消息内容
- **敏感信息**：不存储用户敏感信息

### 配额保护

- **防滥用**：配额限制防止恶意使用
- **管理员特权**：管理员无配额限制

### 隐私保护

- **数据最小化**：仅收集必要数据（Telegram 用户 ID、昵称与对话内容）
- **数据保留**：对话历史存于 MySQL，用户可随时通过 `/clear` 命令清除本人的对话记忆

## 📝 配置参考

### 环境变量

| 变量 | 说明 | 默认值 | 必需 |
|------|------|--------|------|
| QA_BOT_TOKEN | 问答Bot的Token | - | 是 |
| QA_BOT_ENABLED | 是否启用问答Bot | True | 否 |
| QA_BOT_USER_LIMIT | 每用户每日限额（config.json `qa_bot_quota` 优先） | 3 | 否 |
| QA_BOT_DAILY_LIMIT | 每日总限额（config.json `qa_bot_quota` 优先） | 200 | 否 |
| QA_BOT_RUNTIME | 问答 Bot 运行时（go/python），config.json 可在线切换覆盖 | go | 否 |

### Docker部署

问答 Bot 无需单独的 compose 服务：`docker-compose.yml` 只有 `sakura-summary-bot` 一个服务，问答 Bot 由主容器内的主进程自动托管（`QA_BOT_ENABLED` + `QA_BOT_TOKEN` 即可，缺省运行 Go 二进制 `sakura-qa`）：

```bash
docker compose up -d
```

查看问答 Bot 日志：

```bash
# 主容器日志（含问答子进程输出）
docker compose logs -f sakura-summary-bot

# 问答 Bot 组件日志
docker compose exec sakura-summary-bot tail -n 100 logs/qa-bot.log
```
