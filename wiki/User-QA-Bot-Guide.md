# 小妲助手使用指南

适用于 **Sakura-Bot v2.4.8 的 Go 助手运行时**。小妲使用独立的 Telegram Bot Token，与主 Bot 共用配置、MySQL、频道检索和 Wiki 工具。主 Bot 负责启动和托管助手进程。

## 启用助手

在 BotFather 创建助手 Bot，并在 `data/.env` 中配置：

```dotenv
QA_BOT_TOKEN=your_assistant_bot_token
QA_BOT_ENABLED=True
QA_BOT_RUNTIME=go
QA_BOT_USER_LIMIT=3
QA_BOT_DAILY_LIMIT=200
```

助手 Token 必须与主 Bot 不同。正常启动主进程或 Docker Compose 即可，不需要另建第二个助手容器，也不要让 Python 与 Go 同时消费一个助手 Token。

旧 Python 运行时保留兼容用途；本页的积分、订阅门槛、评论区、动态追问和原生富文本功能只在 Go 实现。

## 私聊提问与追问

打开助手私聊，发送 `/start`，随后直接提问。例如：

> 最近频道讨论了哪些模型？

小妲会按需要调用频道检索、Wiki 等现有工具。继续发送问题时：

- 上一回合仍在生成或执行工具：新消息进入同一回合，工具批次结束后再注入，已有结果不会被清空或重复执行。
- 上一回合已经关闭：开启下一回合，读取该作用域的会话历史。
- 不同用户可以同时生成。私聊、频道帖子以及讨论群中的普通群聊或话题分别保存会话。

所有阶段共用一个回答流。私聊先显示临时富文本预览，生成完成后发送正式回答；群组持续编辑同一条回答，超长内容才分段。生成期间显示 typing。

默认单回合最多接纳 8 条消息、最长 180 秒（含排队）。队列满、消息数超限或权限不足时会明确拒绝，未接纳消息不扣费。

图片输入仍取决于当前 AI 服务是否开启并支持视觉能力。无说明的图片可先进入当前作用域的图片上下文，再发送文字提问；活动回合中的图片追问会按新消息接纳。

## 免费次数、积分与签到

普通用户优先使用每日免费次数；免费次数耗尽后，每条新接纳的问题或追问消耗 **1.0 积分**。

在已经启用评论助手的频道所关联讨论群中，发送精确消息：

```text
签到
```

每个 Telegram 用户每个计费日只能签到一次，均匀随机获得 **0.1～5.0 积分**，以 0.1 为步长。积分永久有效，不能转给其他用户。

- 签到、帮助和状态查询不消耗 AI 次数。
- 同回合三条用户消息按三条计费；工具调用、模型内部重试和流式分片不额外收费。
- 积分消息同样计入全站每日上限，不能用积分绕过全站保护。
- 管理员沿用现有计费豁免。
- 回合失败或取消时，该回合已接纳消息按原计费来源逐条退款；重复退款不会重复返还。
- 重复 Telegram Update 不会重复扣费。

使用 `/status` 查看免费次数、当日消息用量、积分余额与当前回合状态。

默认在 **UTC 00:00** 重置。管理员可在 WebUI 选择业务时区，例如 `Asia/Shanghai`；签到、免费额度和全站上限使用同一个日期边界。

## 必订阅频道

管理员开启订阅门槛后，需要加入全部指定频道才能调用助手 AI。未满足条件时，助手提供加入按钮和“我已订阅”按钮。

加入后点击重新验证，再发送问题。帮助、状态查询与订阅引导始终可用。Telegram 验证服务异常时不会直接放行。

配置验证使用 **助手 Bot 自己的身份**。主 Bot 是频道管理员，并不代表助手具备权限。

## 评论区与关联讨论群问答

管理员在 WebUI → **AI 配置 → 小妲助手 → 评论区助手** 中：

1. 从现有频道列表中选择需要启用的频道。
2. 为每个频道设置唤醒词，默认“小妲”。
3. 确认频道已关联讨论群，并将助手加入该讨论群。
4. 关闭助手的群隐私模式，或将其设为讨论群管理员，以便收到普通消息、可见评论和连续追问。
5. 点击“检查助手权限”，修复诊断问题后保存。

用户可以在频道实际关联的讨论群中直接提问，也可以进入某个帖子的评论串。消息开头使用唤醒词，允许前导空白。

> 小妲，结合大家的评论总结一下这篇帖子。

还可以通过 Telegram 的 @提及选择实际助手 Bot，或回复助手 Bot 的消息。@提及按 Telegram 实体和助手的真实用户名或 ID 匹配。同一用户在同一作用域内已有活动回合时，继续发消息即可追问。回合结束后，使用唤醒词、@提及或回复助手消息开始下一回合。

入口限定为已启用频道实际关联的讨论群。唤醒词、@提及和回复关系决定是否触发，传给模型的用户原文包含完整唤醒词、标点与空白。

能映射到频道帖子的评论使用原帖作用域和已收集评论快照。群内直接提问使用群组或话题作用域，回复普通成员的不同消息时仍沿用该作用域。助手在提问所在群组或话题回复。频道转发的帖子按当前频道的讨论串关联，其他用户的公共评论作为帖子参考资料。

多频道共用讨论群时，每条消息只触发一次。显式唤醒词和已映射帖子使用所属频道的设置。未指明频道的匿名 @提及、回复和活动回合追问，按配置顺序选择第一个允许匿名身份的已启用关联频道。

### 本群匿名管理员

在对应频道的“评论区助手”设置中开启“允许本群匿名管理员使用助手”，并设置“匿名管理员群组每日共享额度”。此授权默认关闭，额度默认 **20 次/日**，可设置为 1–1000 次。

本群匿名管理员以 Telegram 提供的当前群组身份发送消息，可使用相同的唤醒和追问方式。助手按群组身份保存独立会话，群内多个匿名管理员共享该身份与每日额度。不同群组、帖子和话题的会话分别保存，群级额度按业务时区重置并计入全站每日上限。

匿名身份隐藏了真实账号，个人订阅状态无法验证。开启此授权即允许当前群组身份按匿名策略使用助手，包括已设置必订阅频道的情况。准入策略在 WebUI 开关说明和匿名 `/status` 中展示。授权成功后的提问直接进入正常回答。匿名身份使用群级硬额度，个人积分与签到适用于真实用户账号。

身份验证依据 Telegram 的当前群组发送身份。外部频道身份、自动转发帖子、其他机器人、系统消息与编辑旧消息均会被过滤。

主 Bot 的 `@admin 举报` 和 `@admin 上报` 配置见 [Sakura Guard 智能群管](User-Sakura-Guard.md)。

### 收不到唤醒消息时

运行“检查助手权限”，查看助手身份、实际关联讨论群 ID、群内成员或管理员状态，以及群隐私模式。具备普通消息接收权限后，在该讨论群发送一次唤醒词验证实际投递。必订阅频道的成员验证还要求助手在相应频道拥有管理员权限。

### 评论上下文的边界

助手保存原帖、已收集评论、回复关系、媒体说明和可见编辑，并按时间组织整个帖子的快照。不同帖子的资料互不混用。

这个快照不是 Telegram 实时完整历史：Bot API 无法通用遍历接入前历史，也不能获知所有删除或账号不可见内容。视频、语音等没有被解析的媒体只保留可见说明，不会假装已读取内容。

需要补充历史时，展开“回溯历史评论”，选择已启用频道并填写原频道帖子 ID。系统使用现有已登录的 UserBot 读取其可见历史，幂等导入且不覆盖实时记录。达到本次上限或超时会明确提示。

## 常用命令

| 命令 | 用途 |
| --- | --- |
| `/start`、`/help` | 开始使用、查看帮助 |
| `/ask <频道> <问题>` | 在私聊中限定查询频道 |
| `/status` | 查看免费次数、积分与回合状态 |
| `/clear` | 取消当前作用域的回合并清除该作用域历史与图片上下文 |
| `/view_persona` | 查看人格配置 |
| `/listchannels` | 列出可用频道 |
| `/subscribe`、`/unsubscribe`、`/mysubscriptions` | 管理总结推送订阅，与必订阅门槛分开 |
| `/request_summary <频道>` | 向管理员提交总结请求 |
| `/submit`、`/cancel_submit` | 投稿及取消投稿 |
| `/appeal`、`/appeals`、`/cancel_appeal` | Sakura Guard 申诉 |

已启用的关联讨论群和评论区支持 `/status`、`/help` 和 `/clear`。投稿与申诉通过助手私聊处理。

## 配置保存与生效

WebUI 沿用现有主题：浅色为 Google 控制台风格，深色为 X 风格。配置有“已同步／有未保存的修改”状态，完成编辑后点击“保存助手配置”。

频道启停、唤醒词、订阅开关、签到、业务时区、匿名授权和共享额度保存后热生效。助手在接纳消息及开始执行前重新核实关联关系与准入权限。执行并发数、队列容量、每用户并发作用域数、回合消息上限、Inbox 容量与超时在重启助手后生效。

详见 [多轮对话与活动回合](User-Multi-Turn-Conversation.md)、[WebUI 管理面板](User-WebUI-Guide.md) 与 [Go 助手架构和迁移](Developer-QA-Turns-Billing.md)。
