## 📖 概述

Sakura-Bot WebUI 是一个基于 Vue 3 + Naive UI 的 Web 管理界面，提供 14 个功能页面，覆盖频道管理、总结调度、转发规则、AI 配置、群管与数据运维等能力，无需通过 Telegram 命令即可完成大部分管理操作。

v2.2.1 起界面按平面设计系统全面重构：浅色主题对齐 Google 控制台风格、深色主题对齐 X 风格；页面统一「页头 + 工具栏 + 数据区」骨架，数据加载均有骨架屏、空态引导与错误重试三态呈现；危险操作按风险等级采用行内二次确认、独立危险卡与高危对话框三层确认体系。

### 页面导览

侧栏菜单按信息架构分为 5 个分组、共 14 个页面（窄屏 ≤760px 时侧栏自动收起为图标栏）：

| 分组 | 页面 | 说明 |
|------|------|------|
| 概览 | 仪表板 | 一屏总览 Bot 运行状态与核心指标，常用页面一键直达 |
| 概览 | 统计数据 | 总结产出与消息规模总览，查看各频道贡献排名与历史总结 |
| 频道与内容 | 频道管理 | 管理监控的频道，可随时生成总结或移除频道 |
| 频道与内容 | 机器人群组与频道 | 核实机器人在各群组与频道中的身份，批量退出与清理已销号成员 |
| 频道与内容 | 转发规则 | 可视化管理频道转发规则 |
| AI 与知识库 | AI 配置 | 配置模型提供商、API 密钥与提示词，保存后立即生效 |
| AI 与知识库 | 向量存储 | 查看 RAG 向量规模，语义检索与文档清理 |
| 自动化 | 定时任务 | 管理频道自动总结计划与总结进度 |
| 自动化 | 互动设置 | 频道投票、自动投票与评论区欢迎三页签配置 |
| 自动化 | 命令中心 | 按分类浏览命令目录，已接入的命令可直接执行 |
| 系统 | Sakura Guard | 按群管理入群验证、消息过滤与处罚审核 |
| 系统 | 数据库管理 | 浏览 MySQL 表、分页查询与受控数据操作 |
| 系统 | UserBot | 查看真实账号会话状态，执行频道加入/离开操作 |
| 系统 | 系统运维 | 服务状态总览、启停控制、运行日志与数据维护 |

## 🚀 快速开始

### 1. 启用 WebUI

在 `data/.env` 中添加以下配置：

```env
# ===== WebUI 管理面板配置 =====
WEBUI_ENABLED=true
WEBUI_HOST=0.0.0.0
WEBUI_PORT=8080
```

### 2. 启动 Bot

```bash
python main.py
```

Bot 启动后会自动启动 WebUI 服务器。

### 3. 访问面板

打开浏览器访问：

- 本地：`http://localhost:8080`
- 局域网：`http://<服务器IP>:8080`

## 🔐 认证说明

### 管理 Token 登录

WebUI 使用 JWT（JSON Web Token）进行身份验证：

- 登录页输入**管理 Token** 即可登录，无需 Telegram ID
- 管理 Token 是 Bot Token 的 SHA256 哈希前 16 位，Bot 启动时会在日志中打印（`🔑 WebUI 管理 Token: ...`）
- 登录成功后服务端签发 JWT，前端自动携带，有效期内无需重复登录
- Bot Token 未配置时无法登录

### 开发模式

在 `data/.env` 中设置：

```env
WEBUI_DEV_MODE=true
```

设置后登录页会出现独立的「开发模式」按钮（后端通过认证状态接口告知前端是否可用），点击即可使用开发 Token 进入，无需输入管理 Token。

> ⚠️ **警告**：开发模式仅用于本地开发环境，切勿在生产环境中启用！

## 📋 功能详解

### 仪表盘

仪表板每 30 秒自动刷新（右上角可手动刷新），自上而下分为：

- **状态摘要条**：Bot 主程序、QA Bot、数据库三个状态徽标，数据来源失败时显示「未知」而不是假数据
- **统计 tiles**：监控频道、总结总数、转发规则、定时任务四项核心指标
- **运行信息**：版本、AI 模型、日志级别、转发状态与运行时长
- **定时任务概览**：各频道自动总结的执行安排与下次运行时间
- **快捷操作**：频道管理、定时任务、转发规则、命令中心、系统运维、数据库管理一键直达

顶栏的 Bot 在线徽标同样每 30 秒自动探测一次。

### 频道总结生成

总结生成是「频道管理」页的行级操作：

1. 进入「频道管理」页面
2. 在目标频道行点击「生成总结」
3. 等待 AI 完成总结，结果通过页面消息提示反馈

每个频道的生成按钮带独立 loading，互不阻塞，可同时触发多个频道。

### 转发规则管理

转发页面支持可视化管理频道转发规则：

- 启用或禁用全局转发功能
- 添加、编辑、删除转发规则
- 配置关键词/正则白名单和黑名单
- 切换复制模式、只转发原创消息和默认底栏
- 使用底栏模板与占位符快速生成自定义底栏

常用底栏占位符包括：`{source_link}`、`{source_title}`、`{target_title}`、`{source_channel}`、`{target_channel}`、`{message_id}`、`{assistant_bot}`、`{submission}`。

> 配置保存后会显式触发热重载，转发规则通常无需重启即可生效；系统会对重复热重载事件进行去重。

### 互动设置

互动设置页分为「投票设置」「自动投票」「评论区欢迎」三个页签：

- **投票设置**：全局投票设置统一控制总结投票的总开关与重新生成规则，未单独配置的频道跟随全局；支持逐频道添加覆盖配置，行内开关即时保存、失败自动回滚
- **自动投票**：配置自动趣味投票行为
- **评论区欢迎**：配置评论区欢迎行为

逐频道等表单修改采用脏状态提示——有未保存的修改时页面会明确提示，避免改动丢失；行内开关的即时保存失败时会自动回滚。

### 命令中心

按分类浏览机器人命令目录，已接入的命令可在页面直接执行；高危命令需要输入确认文案二次确认。

### 向量存储

向量存储页用于查看 RAG 知识库规模：

- 顶部统计 tiles 展示各集合的文档数量
- 「语义搜索」卡片支持输入文本进行语义检索，结果附带相似度进度条
- 提供文档删除与清空操作（均需二次确认）

### Sakura Guard

Guard 页面按群管理入群验证、消息过滤规则与处罚审核，全部设置自动保存；记录区提供案件/处罚日志、本群白名单、全局永久黑名单、入群验证与通知投递五类记录表。详细说明见 [Sakura Guard 指南](User-Sakura-Guard.md)。

### 数据库管理

数据库页面采用「表列表 + 数据预览」双栏布局：

- 左侧选择允许管理的数据表（显示行数），右侧按页浏览数据
- 新增、编辑、删除单行数据
- 提供按天数清理旧数据的工具（转发记录、投票重生成记录、操作审计）
- 清空数据并重启等高危操作不在本页，统一收口在「系统运维」页的危险区（见下文）

> ⚠️ 数据库管理属于高危功能。操作前请确认已备份数据，并仅允许可信管理员访问 WebUI。

### 系统运维

系统运维页顶部为状态总览（主 Bot、频道、QA Bot、数据库四张状态卡，QA Bot 卡同时显示配置与实际运行时），下方分三个页签：

- **运行控制**：主 Bot 的暂停/恢复/重启、配置重载与日志级别调整；QA Bot 的启动/停止/重启与健康检查；支持在 **Go 与 Python 运行时**之间一键切换 QA Bot，切换会写入 `data/config.json` 持久化并立即重启问答 Bot（进行中的问答会话会中断），详见 [QA Bot 指南](User-QA-Bot-Guide.md)
- **运行日志**：按行数、级别与关键字过滤查看日志，支持自动滚动与一键复制
- **维护**：按天数清理转发记录、投票重生成记录与操作审计；查看最近的 WebUI 操作审计表；「危险区」集中提供清理讨论组缓存、清空数据库并重启等高危操作，需多层确认

### 配置保存即时生效

WebUI 保存配置后会主动触发配置热重载，使以下配置更快应用：

- AI 客户端与提示词配置
- 自动总结调度任务
- 频道转发规则和底栏模板
- 日志级别等运行时配置

如果外部工具直接修改 `data/config.json`，文件监听仍会处理变更；WebUI 保存与文件监听同时触发时会尽量去重。

### 深色主题

WebUI 支持深色/浅色主题切换：

- 点击右上角主题切换按钮
- 主题选择会自动保存到浏览器（localStorage `sakura_bot_theme`）
- 下次访问时自动应用上次选择的主题

v2.2.1 起两套主题分别对齐 Google 控制台（浅色）与 X（深色）的视觉风格，均基于 `--sb-*` 平面设计令牌构建。

## ❓ 常见问题

### 无法访问 WebUI

1. 确认 `WEBUI_ENABLED=true` 已设置
2. 检查防火墙是否放行了 WebUI 端口
3. 确认 Bot 已正常启动并初始化了 WebUI

### 登录失败

1. 确认 `.env` 中 `TELEGRAM_BOT_TOKEN` 已正确配置（未配置时无法登录）
2. 确认输入的管理 Token 与 Bot 启动日志中的 `🔑 WebUI 管理 Token` 一致；修改 Bot Token 后管理 Token 会随之变化，以最新一次启动日志为准
3. 使用「开发模式」按钮时，确认 `WEBUI_DEV_MODE=true` 已设置并重启了 Bot

### 深色主题不生效

- 清除浏览器缓存后重试
- 确认浏览器支持 `localStorage`

### 配置保存后没有生效

1. 确认保存请求返回成功
2. 查看 Bot 日志中是否出现配置重载错误
3. 对转发规则，确认源频道和目标频道可被 Bot 或 UserBot 访问
4. 如仍未生效，可通过 WebUI 或命令执行优雅重启

### 数据库管理操作失败

1. 确认当前用户是管理员
2. 确认 MySQL 连接正常
3. 检查目标表和列是否在允许管理范围内
4. 查看日志中的详细错误，避免重复提交危险操作

## 🏗️ 技术架构

WebUI 采用前后端分离架构：

- **后端**：FastAPI (Python) - 提供 RESTful API，作为 asyncio 任务运行在主进程中，与 Bot 共享配置和数据库服务
- **前端**：Vue.js 3 + Vite + Naive UI - 单页应用，基于 `--sb-*` 平面设计令牌构建双主题界面
- **认证**：JWT Token（管理 Token 登录）
- **路由**：SPA 路由（前端路由 + 后端 fallback）
