# 频道图片采集与识别

## 数据流与启用

主 Bot 为可见的照片、相册成员以及以文件发送的 PNG/JPEG 登记后台图片任务。每张图片保留独立的 Telegram 消息 ID、原帖链接、完整说明、原始时间和相册分组。

在 **AI 配置 → 用途绑定 → 图片识别** 选择支持图片输入的模型，再开启「频道图片 OCR / 描述」。OCR 和描述可分别开启。配置厂商和模型的方式见[AI 厂商与用途](AI_PROFILES.md)。

```json
{
  "ai_vision": {"enabled": true, "ocr": true, "description": true},
  "ai_routing": {"vision": {"provider_id": "service", "model_id": "vision-model", "supports_vision": true}}
}
```

关闭视觉时，已存储的图片可保留为 `stored`，启用后继续识别。助手私聊选图使用助手自己的图片能力开关。

## 持久化和读取

- 内容寻址的文件存入数据目录下的图片存储。MySQL 的 `image_assets` 记录哈希、文件属性、OCR、描述与模型。 `message_images` 保存每条原帖引用和处理状态。
- 相同图片哈希可共享文件及识别结果。后台任务通过租约和来源版本核对，崩溃后可恢复过期租约。
- 下载限制包含实际体积与文件签名检查。视觉请求从受控图片目录读取文件。普通日志与检索历史只保存业务所需的结果和引用。
- OCR、描述和原始说明可共同参与消息 RAG 索引。已识别但索引暂时失败时，持久化的 OCR 和描述仍可被总结或投票使用，索引可单独重试。

## 周报与投票

频道历史提取先登记本批图片，再读取准备好的 OCR 和描述。图片正在识别时，同频道的这批图片共享约 20 秒等待窗口。若仍有活跃图片任务，系统保留总结进度并给出重试提示，避免将队列状态当作原文交给模型。图片任务终止失败时会记日志，并尝试使用原始说明。

自动趣味投票可对静态图片、图文和相册投票。投票模型能识图时可直接使用图片。文本投票模型优先读取已保存的 OCR 和描述，缺失时通过视觉路由补齐识别并保存结果。

## 状态、重试与历史补录

管理员 API 需要 WebUI 登录态和 Bearer 凭据。

| 路由 | 用途 |
| --- | --- |
| `GET /api/images/stats` | 按状态统计图片任务与失败尝试 |
| `GET /api/images/{channel_id}/{message_id}` | 核对单条图片的任务状态 |
| `POST /api/images/{channel_id}/{message_id}/retry` | 提交 `{"force": false}` 重试。显式指定 `true` 时作废相应识别缓存 |
| `POST /api/images/backfill` | 通过已授权历史客户端为配置中的频道补录图片任务 |

以下请求体用于补录某个频道的历史图片任务。

```json
{
  "channel": "https://t.me/configured_channel",
  "start": "2026-01-01T00:00:00Z",
  "end": "2026-02-01T00:00:00Z",
  "limit": 1000
}
```

时间段使用原帖日期。 `limit` 限制扫描消息数，范围为 1–100000。接口登记任务后返回，新识别由后台处理。重复补录会按已登记消息身份处理。

## 编辑、删除与备份

图片被替换或移除后，后续读取按当前消息的媒体身份与版本校验。原帖删除会撤销关联及索引，后台旧任务无法覆盖已经失效的结果。一个图片文件可能仍被其他原帖引用。

备份时保留 MySQL、数据目录下的图片文件与向量索引。独立环境可用 `go test ./internal/media ./internal/rag ./internal/summary` 验证采集、索引和总结路径。
